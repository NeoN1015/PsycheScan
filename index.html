Fusion, Models, and Dataset Notes

Sensor reference used in this package

The uploaded stress-detection paper highlights multimodal stress evidence such as electrodermal activity, motion, and temperature. This dashboard keeps the live operator view cleaner by focusing the visible sensor status on the core four channels: heart rate, GSR, temperature, and motion.

Why weighted fusion matters

The same paper reports better stress performance from weighted score-level fusion than feature-level fusion, so this dashboard keeps face evidence and each sensor stream separable before combining them into one live risk score. That makes later backend training cleaner and more adaptable per participant.

Recommended facial-expression datasets

Use AffectNet and RAF-DB for in-the-wild robustness, FER+ for noisy web-style faces, and CK+ for controlled sequence benchmarking. Keep WESAD as the multimodal stress-side reference, not as a facial-expression dataset.

Practical build guidance

Browser-ready face stack

The app can use face-api.js now, with strong mode preferring SSD Mobilenet when available. Captured session data and participant indexing are synchronized to the backend database instead of living only in the browser.

Transport options

USB Serial fits Arduino-class boards, Bluetooth LE fits ESP32 BLE bridges and wearable-style peripherals, and WebSocket fits ESP32 Wi-Fi or Node relay bridges. All three paths map into one JSON packet parser.

Privacy boundary

This build stores sessions, reports, settings, and participant indexing in a local SQLite database, while using browser cache for resilience. It still needs user consent, device control, and clear disclosure because local deployment is not a substitute for clinical governance.
