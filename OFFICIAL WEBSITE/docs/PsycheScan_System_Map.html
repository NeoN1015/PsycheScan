How PsycheScan works

Real-Time Early Detection System for Mental Health Using Vital Signs Sensors Applying Hybrid CNN-LSTM Algorithms for In-Depth Analysis of Stress and Anxiety Parameters

PsycheScan screens a participant for stress and anxiety by combining two independent evidence streams: four vital signs from an ESP32 sensor device, and facial analysis from a USB webcam. Both are fused into one Integrated score on a four-level scale, and an LSTM network reports the sustained trend. Everything runs locally on one mini PC.

Measure · ESP32 firmware

Four sensors, one packet every 500 ms

When a sensor goes quiet

  • The card keeps the last valid reading, shown faded and marked as held, so the screen and charts stay stable.
  • The sensor's badge changes to Waiting or Disconnected.
  • Held values are tagged in history and records, and are kept out of the LSTM and the baseline, so stale data never trains a decision.
  • The score uses live sensors only.

Decide · score-level fusion

One Integrated score from three risks

Emotion, visual fatigue and the sensor level are each turned into a 0–100 risk and averaged with fixed weights. Only the streams that are present count, and their weights are rescaled, so the score still means something with no face or no sensor. Code: computeAssessment in main.js.

Where each risk comes from

emotion = 100 × (sad + angry + fearful + 0.8 × disgusted + 0.35 × surprised) + 0.3 × confidence if the dominant emotion is negative (max 100) fatigue = visual fatigue score (0–100) sensors = 0 · 33 · 66 · 100 from the vote

Sensor vote and levels

  • Each live sensor votes its own level; GSR casts two votes.
  • The most severe level with any vote becomes the sensor level.
  • Integrated levels: 0–24 25–44 45–69 70–100
  • Trend: last 6 scores vs the 6 before: over +4 Rising, under −4 Falling.
Decide · temporal model

The LSTM reads the last minute, not the last second

The LSTM is the temporal half of the CNN-LSTM design. Every 5 s it takes the last 60 seconds of all four vital signs and classifies the sustained level, so a brief spike, like a finger slipping off the sensor, doesn't change its answer. It runs in a background worker and is reported beside the Integrated score, not inside it.

When it is allowed to predict

  • Each second uses the latest complete reading, at most 3 s old.
  • At least 80% of the 60 seconds are fresh; until then the badge counts up, e.g. "16/60 S".
  • Held (disconnected) readings never enter the sequence.
Show · a session

One session, start to end

What the operator does, in order. Every reading is tied to one patient profile.

  1. Start the serverRun start_server.bat and set the operator password.
  2. Sign inOpen http://localhost:8000. Saved data loads from /api/bootstrap.
  3. Choose the patientSelect or add a profile, then fit the sensors.
  4. Connect the deviceUSB, Bluetooth or Wi-Fi. Packets start every 500 ms.
  5. Start the cameraLoad Models, Start Camera. Detection every 160 ms.
  6. Capture the baseline3–5 minutes at rest. Averages are stored on the profile.
  7. MonitorLevels, charts and the LSTM trend update live; records save every 3 s.
  8. Review and exportStatus Summary, then CSV or PDF from Reports.
Baseline phaseResting readings become the reference: HR and GSR averages for the percentage rules, and temperature for the drop.
Questionnaire phaseLive readings are compared with the baseline; the Live Monitoring Hub shows the difference.
RecordsSaved at most every 3 s when a face (≥ 30%) or a sensor is present, each with a matching report row.
Keep · server and database

Two copies, never overwritten

The browser keeps a working copy so monitoring continues if the server blinks. server.py keeps the permanent copy in SQLite. Each save carries a revision number; if another window saved first, the server answers 409 and the browser reloads instead of overwriting.

Protection

  • Operator password set at startup; token lives only in the open tab.
  • 5 failed sign-ins in 60 s blocks that address briefly.
  • Requests must come from the same site; bodies capped at 1 MB.
  • Local test mode accepts only the same computer.
  • Readings older than 30 days are removed at startup.

Boundaries

Screening support, not diagnosis

Responsible use

  • A screening and decision-support tool. A qualified professional makes the final interpretation.
  • Participants aged 18–65 who gave informed consent.
  • All data stays on the local machine, in line with RA 10173, the Data Privacy Act of 2012.

Known limits and next steps

  • 30 participants from one clinic; more sites and people are the clear next step.
  • Integrate the trained EfficientNet-B0 CNN into the live dashboard.
  • Retrain the live LSTM on labelled participant sessions.
  • Validate the levels against clinician ratings.
